# Bookmark Sync Bridge

在多个 Chromium 系浏览器之间同步书签，**数据只在本机 `127.0.0.1` 流转，不经过任何云端服务**。

A local-first bookmark sync bridge for Chromium-family browsers. No cloud, no account, no external dependencies.

---

## 为什么需要它

- 不同浏览器的书签互相独立，改动无法互通。
- 浏览器自带的云同步会合并多个来源，一旦某处出现重复书签，重复数据会被扩散到所有设备、且难以清除。
- 本项目把同步收敛到一台机器：**一台主浏览器 + 多个从浏览器**，从浏览器严格跟随主浏览器，且提供多层本地备份。

## 架构

```
  主浏览器 (master)               从浏览器 (follower)
  ┌──────────────┐              ┌──────────────┐
  │  扩展        │              │  扩展        │
  │  · 变化即推送 │              │  · 启动时拉取 │
  └──────┬───────┘              │  · 每日 1:00 │
         │  POST /push          └──────▲───────┘
         ▼                            │ GET /pull
  ┌──────────────────────────────────┴──────┐
  │  本地服务 (Python, 127.0.0.1:8765)        │
  │  · 主树 master.json                      │
  │  · 每日存档 backups/                     │
  │  · 便携备份 书签汇总备份.html             │
  │  · 书签文件守护（恢复 / 去重）             │
  └──────────────────────────────────────────┘
```

**同步方向是单向的**：主 → 从。从浏览器不会自动把改动写回主树；如需回传，请在从浏览器手动点击「立即推送」。

## 快速开始

### 1. 启动本地服务

需要 Python 3.8+，**无第三方依赖**。

```bash
cd server
python bookmark_sync_server.py
```

Windows 用户也可以双击 `server/start.bat`；Linux/macOS 用 `./server/start.sh`。

服务默认监听 `127.0.0.1:8765`。验证：

```bash
curl http://127.0.0.1:8765/health
# {"ok": true, "urls": 0, ...}
```

### 2. 安装扩展

1. 打开 `chrome://extensions`（Edge 为 `edge://extensions`）
2. 开启「开发者模式」
3. 点击「加载已解压的扩展程序」，选择本仓库的 `extension/` 目录
4. 在需要同步的每个浏览器里各安装一次

> 扩展源文件必须保留在磁盘上。这是 unpacked 扩展，删除目录会导致扩展失效。

### 3. 设置角色

点击扩展图标，在「角色」下拉框中选择：

| 角色 | 选择谁 | 行为 |
|---|---|---|
| **主**（master） | 你日常维护书签的那个浏览器 | 书签变化自动推送；不自动拉取 |
| **从**（follower） | 其余浏览器（默认值） | 打开浏览器时、以及每天凌晨 1:00 自动与主对齐；不自动推送 |

点「保存角色设置」后即刻生效。

### 4. 日常使用

- 在**主浏览器**增删改书签、调整文件夹顺序，改动会推送到本地服务。
- **从浏览器**下次启动时（或凌晨 1:00）会完整对齐：新增、删除、改名、移动、排序**全部同步**。
- 从浏览器临时加了书签想保留：手动点「立即推送」。

## 配置

复制 `server/config.example.json` 为 `server/config.json` 后可调整：

| 项 | 默认 | 说明 |
|---|---|---|
| `port` | `8765` | 修改后需同步修改 `extension/manifest.json` 的 `host_permissions` 与 `extension/background.js` 的 `SERVER` |
| `keep_days` | `14` | 存档保留天数 |
| `guard_interval` | `4` | 书签文件守护检查间隔（秒） |
| `auto_discover` | `true` | 自动发现 Chrome / Edge / Chromium / Brave / Vivaldi 的 Bookmarks 文件 |
| `guard_targets` | `[]` | 非标准路径浏览器的 Bookmarks 文件，手动列出 |

`config.json` 已被 `.gitignore` 忽略，不会上传。

## 安全设计

1. **只监听回环地址**，不接受外部连接。
2. **主树替换安全阀**：主浏览器推送的书签数若比现有主树少 30% 以上，服务端拒绝替换、降级为只增合并，避免一次误删扩散。
3. **对齐安全阀**：从浏览器在对齐前会检查主树是否异常（为空 / 数量骤降），异常则跳过。
4. **对齐前自动存档**：从浏览器重建书签前，先把当前书签推送到服务端存档，出错可回溯。
5. **并发锁**：启动时的多个拉取事件串行执行，避免重复写入。
6. **结构指纹**：比较有序树结构，完全一致时不做任何重建。

## 备份

| 副本 | 位置 | 说明 |
|---|---|---|
| 主树 | `data/master.json` | 程序可读 |
| **便携备份** | `data/书签汇总备份.html` | 标准 Netscape HTML，**任何浏览器都能直接导入** |
| 每日存档 | `data/backups/<日期>_<浏览器>.json` | 每个浏览器每天 1 份，保留 14 天 |
| 各浏览器自身 | 各自 profile | 每台浏览器都是一份独立副本 |

`data/` 不纳入版本控制，请勿提交真实书签数据。

## 已知限制

- **Chrome 账号书签**：Chrome 127+ 登录 Google 账号并开启书签同步后，书签会转为「账号书签」，本地 `Bookmarks` 文件为空。扩展仍能正常读取，但退出账号后看不到书签。**同时开启浏览器云同步与本项目，可能重新引入重复数据，建议二选一。**
- 从浏览器上手动添加但**尚未推送**的书签，在下次对齐时会被清除（这是"严格跟随主"的预期行为）。
- 服务需要保持运行；开机自启请在操作系统层面自行配置。
- 仅支持 Chromium 系浏览器，Firefox / Safari 不适用。

## API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/health` | 健康检查 |
| GET | `/pull` | 返回主书签树 |
| POST | `/push` | `{"browser":"chrome","role":"master","tree":{...}}` |
| GET | `/stats` | 各浏览器最近推送情况 |
